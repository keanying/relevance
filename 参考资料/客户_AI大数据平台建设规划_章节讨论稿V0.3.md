# 票付通AI大数据平台建设规划

## 章节讨论稿 V0.3：以数据治理为基础，建设可持续演进的AI大数据平台

本稿用于对齐未来1—3年的能力建设方向，按平台能力组织内容，暂不展开具体排期、组织流程和实施细节。

**总体目标：通过1—3年的持续建设，形成数据可信、模型可复用、服务稳定、能力易扩展的AI大数据平台，持续支撑对内赋能、对外商业化及行业成果输出。**

建设主线是：以数据治理解决当前的数据问题，以统一平台承载公共能力，以AI与数据服务扩大使用价值。

现有DataWorks离线能力、动态数据开放API服务和QuickBI是本次建设的基础。重点在于整合已有能力、补齐治理与模型体系，并持续扩展实时处理、指标管理、景区自主分析和AI能力。

## 章节总览

| 章节 | 核心内容 | 要形成的能力 |
|---|---|---|
| 一、建设起点与平台目标 | 当前问题、已有能力、目标架构 | 明确治理重点和平台演进方向 |
| 二、统一数据底座 | 数据接入、离线、实时、湖仓、公共模型 | 数据统一沉淀和加工，支撑多场景复用 |
| 三、数据治理与资产平台 | 数据地图、血缘、质量、标准及权限 | 数据可发现、可理解、可信、可追溯 |
| 四、指标与自助分析平台 | 企业标准指标、景区自定义指标、BI与分析 | 统一企业口径，支持景区自主分析 |
| 五、AI平台与智能应用 | 知识、模型与工具服务，问数、预测和助手 | AI贯穿数据开发、业务分析和日常服务 |
| 六、数据服务与价值转化 | 标准接入、开放服务、行业成果、商业化 | 将平台能力转化为可交付的产品和服务 |

## 一、建设起点与平台目标

### 1.1 当前需要解决的五类问题

以下现状依据本轮业务说明。

| 当前问题 | 建设重点 | 期望改变 |
|---|---|---|
| 数据分散在各系统，孤岛严重 | 统一接入、对象关联和共享数据模型 | 跨系统数据可关联、可分析、可复用 |
| 景区及业务线相同指标口径不同 | 企业标准指标、统一语义和版本管理 | 同一标准指标在不同出口含义和结果一致 |
| 表、字段、DDL和描述不规范 | 从源系统到模型、接口和报表建立数据标准 | 数据结构有规范，字段含义明确，变更可管理 |
| 离线与湖仓模型重复开发 | 公共明细、统一维度、主题模型和共性计算逻辑 | 新需求优先复用已有模型，减少重复建设 |
| 入园、核销等数据准确性不足 | 源端采集校验、链路对账、质量规则和问题追溯 | 关键数字可验证，异常可定位和修复 |

### 1.2 已有能力与本次建设的关系

| 已有能力 | 继续承担的作用 | 本次需要完善的部分 |
|---|---|---|
| DataWorks（离线） | 现有离线数据加工基础 | 统一开发与建模规范，衔接质量、元数据、血缘和发布管理 |
| 动态数据开放API服务 | 将ADS层指标快速作为服务向内外提供 | 关联标准指标及版本，完善质量状态、权限、服务监测和计量 |
| QuickBI | 现有BI分析与展示入口 | 接入治理后的模型与指标，承接自助分析及景区个性化分析 |

具体能力复用范围需结合当前版本和配置确认。指标管理及景区自定义等需求，根据现有工具的支持程度采取配置、集成或补建。

### 1.3 平台目标结构

以现有工具为基础，贯通数据接入、加工治理、指标生产、分析与API服务，使AI使用同一套可信数据和权限体系。

| 能力层次 | 核心组成 |
|---|---|
| 数据基础 | 多源接入、离线处理、实时计算、湖仓存储、公共数据模型 |
| 治理与资产 | 标准、地图、血缘、质量、权限、资产目录 |
| 指标与分析 | 企业标准指标、景区专属指标、统一语义、自助BI |
| AI能力 | 模型服务、知识检索、工具调用、评测、智能分析与预测 |
| 产品与服务 | 内部经营、景区运营、合作伙伴接入、行业报告与数据产品 |

### 1.4 平台服务对象

- **企业内部：** 经营决策、运营分析、数据开发、产品研发、客服及实施。
- **景区客户：** 经营分析、自定义指标、运营预警、AI辅助决策。
- **合作伙伴：** 数据接入、指标调用、嵌入式分析和AI能力集成。
- **行业服务：** 行业洞察、经营对标、研究报告及规范输出。

## 二、统一数据底座

**建设目标：把分散在各业务系统的数据沉淀为可复用的数据基础，兼顾历史分析和实时业务需求。**

### 2.1 数据接入与整合

统一业务库、渠道接口、设备事件、行为日志、知识文档和获授权外部数据的接入规范，补齐分散系统的数据回流及关联关系。接入时明确来源、更新方式、对象标识和负责人。

重点覆盖以下数据域，实际可用范围以盘点为准：

| 数据类别 | 主要内容 |
|---|---|
| 资源与商品 | 景区、供应商、票种、套餐、场次、价格、库存 |
| 交易与履约 | 订单、支付、退款、预约、票券、核销 |
| 渠道与结算 | 分销关系、渠道订单、佣金、账单、结算 |
| 用户与营销 | 会员、权益、活动、优惠券、访问和转化行为 |
| 运营与服务 | 设备、工单、客户使用、多业态消费 |
| 知识与外部信息 | 产品文档、业务规则、行业经验、天气及授权外部数据 |

### 2.2 离线、实时与湖仓能力

- **离线处理：** 依托现有DataWorks离线能力，承接历史加工、复杂分析、周期汇总、对账及重算。
- **实时计算：** 交易与核销变化、业务监控、异常识别和及时预警。
- **湖仓底座：** 统一管理明细与历史数据，支持不同计算和分析场景共享使用。
- **分析查询：** 为BI、AI和接口提供稳定查询服务，管理不同业务的计算负载。

离线与实时是处理方式，湖仓承担统一存储与管理。三者共同服务业务，并保持口径和结果可核对。

### 2.3 公共数据模型

统一租户、景区、商品、订单、票券、渠道等核心对象及关联关系，形成明细、公共维度、主题汇总和应用数据集。

保留明细粒度，既支撑企业标准指标，也支撑景区个性化分析。按业务域统一沉淀公共明细、维度和汇总逻辑，ADS围绕应用输出，减少按景区、报表或接口重复开发模型。

增量需求优先复用标准模型，存量重复模型通过核对和迁移逐步收敛。离线与实时共享业务定义和质量规则，需要分别实现计算时，也保持结果可校验。

### 2.4 稳定性与扩展能力

接入支持新增系统与结构变更，加工支持失败恢复、历史补数及重算，服务支持租户隔离、资源配额及负载监测。通过统一模型和服务契约扩展新业务、新景区与AI应用，降低变更对已有用户的影响。

**预期产出：统一接入能力、离线与实时处理能力、湖仓底座、公共模型及标准数据集。**

## 三、数据治理与资产平台

**建设目标：让数据找得到、看得懂、用得准，问题能够定位，使用范围能够控制。**

| 平台能力 | 建设内容 | 使用价值 |
|---|---|---|
| 数据标准 | 统一表与字段命名、类型、DDL、主键、分区、业务描述、对象编码及变更规范 | 从源端到应用减少结构和语义差异 |
| 数据地图 | 汇集表、模型、指标、报表和接口，展示说明及负责人 | 快速查找和复用数据资产 |
| 数据血缘 | 关联来源、加工过程、指标及下游应用 | 解释数据来源，定位问题与变更影响 |
| 数据质量 | 完整性、准确性、时效性、唯一性及业务一致性检查 | 发现异常并推动修复 |
| 权限管理 | 租户隔离、数据集与字段权限、脱敏及访问记录 | 控制企业、景区和外部伙伴的数据范围 |
| 资产运营 | 使用情况、版本、成本、重复资产与退役管理 | 提升复用效率，控制维护成本 |

上述能力贯穿源系统、接入、离线/湖仓加工、ADS、API、QuickBI和AI，逐步形成统一的数据资产入口。新增表和任务在发布前检查规范，存量按业务影响逐步治理。

### 以入园与核销准确性作为治理样板

先明确“核销次数、有效核销票数、入园人次、去重游客数”的区别，再核查源端采集、订单票券关联、重复上报、离线补传、撤销及统计时间。上述因素为待排查项，不预判为已确认根因。

建立源端记录、加工明细、汇总指标、API及BI之间的核对关系，发现差异后追溯、修复并重算。核销事件不能直接等同游客人数；缺少必要采集时，应补齐数据或明确指标适用范围。

**预期产出：数据地图、血缘与质量能力、权限体系、可持续维护的数据资产目录。**

## 四、指标与自助分析平台

**建设目标：企业统一输出标准口径和模型，景区能够基于自身明细创建专属指标，让统一管理与个性化分析共存。**

### 4.1 企业标准指标与模型

企业统一定义并发布交易、核销、渠道、会员及经营等标准指标，明确计算逻辑、粒度、维度、时间口径和版本。对现有同名异义、同义不同算法进行梳理和收敛，避免QuickBI、API和各业务线分别维护计算口径。

标准指标依托公共数据模型，统一服务报表、自助分析、API和AI问数。企业经营汇总及跨景区比较使用统一标准口径。

### 4.2 景区自定义指标

景区基于获授权的本景区明细、公共维度及可复用标准指标，自主设置计算方式、筛选条件和分析维度，形成符合自身经营需要的指标。

例如，景区可以定义“夜游产品核销占比”“指定票种退款率”或“本景区会员复购率”，用于本景区看板、自助分析和AI问数。

| 管理项 | 企业标准指标 | 景区自定义指标 |
|---|---|---|
| 定义与维护 | 企业统一管理 | 景区授权人员管理 |
| 数据基础 | 企业标准数据模型 | 本景区获授权明细及模型 |
| 使用范围 | 按权限服务企业和景区 | 仅归属并服务该景区 |
| 修改影响 | 统一评审和版本发布 | 不改变企业指标及其他景区指标 |
| 分析标识 | 标明企业标准口径 | 标明所属景区及自定义口径 |

企业标准指标口径不一致属于需要治理的问题；景区为特定经营需求创建专属指标属于受控的产品能力。两者通过明确的指标归属和口径标识区分。

景区自定义指标采用独立标识、版本和权限，同名指标不能覆盖企业标准。隔离覆盖数据查询、缓存、导出、API和AI调用，并通过计算配额避免复杂查询影响其他景区。

有共性价值的景区指标，可经评审沉淀为企业标准；不自动共享或改变原有景区定义。

### 4.3 自助分析与BI

以现有QuickBI作为分析入口，围绕治理后的模型，完善指标检索、明细探索、可视化计算配置、自定义看板和报表订阅。景区指标定义与权限统一管理，按实际工具能力集成到BI使用流程。

企业和景区可以从统一模型及指标出发完成日常分析，减少对技术人员临时取数的依赖。AI问数与BI共用指标定义和权限。

**预期产出：企业指标中心、景区专属指标空间、统一语义服务、自助分析平台及业务看板。**

## 五、AI平台与智能应用

**建设目标：让AI辅助数据治理与开发，让治理后的数据支撑可信的AI分析与业务应用。**

### 5.1 共用AI能力

- **模型服务：** 统一接入和管理模型，支持不同任务选用适合的模型。
- **知识服务：** 管理产品文档、业务规则、实施经验和行业知识，支持带来源的检索与回答。
- **工具服务：** 连接指标查询、数据分析和业务接口，遵循用户与景区权限。
- **评测与运营：** 管理答案质量、版本、反馈、调用成本和运行状态。

### 5.2 AI应用方向

| 应用方向 | 具体能力 |
|---|---|
| AI辅助数据建设 | 字段说明、模型与SQL草稿、质量规则建议、异常排查 |
| AI问数与分析 | 自然语言查询、趋势解释、指标异动分析、报告草稿 |
| AI预测与预警 | 客流预测、交易异常识别、运营风险提示 |
| AI知识助手 | 产品咨询、实施支持、业务规则解释、客服辅助 |
| AI业务助手 | 对账差异分析、工单辅助、接入映射及操作建议 |

AI辅助生成字段描述、模型或质量规则后，由相应负责人确认，不能用模型推测替代业务定义。AI问数通过受控指标与数据服务取数，区分企业标准指标和景区自定义指标，展示口径、来源及质量状态。预测使用专门模型并验证效果，业务操作按权限和流程执行。

**预期产出：共用AI服务、行业知识库、AI问数与分析、预测能力及场景助手。**

## 六、数据服务与价值转化

**建设目标：把统一平台能力转化为内部便捷服务、客户产品、生态接口和行业成果。**

### 6.1 内部与景区服务

将指标、看板、自助分析和AI助手嵌入日常工作及现有产品，支持经营、运营、客服和实施人员便捷使用。景区围绕自身数据形成分析和决策能力。

### 6.2 标准化对接与一键接入

建设标准连接器、接口目录、开发文档、接入向导和运行监测，降低数据输入与能力输出的对接成本。

对已适配的标准系统，在授权和环境就绪后，通过配置完成映射、同步和检查，逐步实现标准场景的一键接入。

复用现有动态数据开放API服务，将治理后的ADS指标快速向内外发布，并关联指标定义、版本、权限和质量状态。在此基础上扩展指标服务、嵌入式BI和AI能力，支持合作伙伴快速集成。

### 6.3 行业报告与规范

依托可用且获授权的数据及多年业务经验，形成经营月报、节假日专题、行业研究、匿名对标和实践指南。

沉淀指标口径、数据模型、接入规范及AI应用方法，逐步开展合作伙伴和行业共建。报告明确样本与统计范围，AI辅助生成，专业人员审核。

### 6.4 数据与AI商业化

围绕景区分析增强版、AI运营助手、标准API、嵌入式分析和行业研究等方向，形成可复用的产品与服务包。

以客户实际使用和付费需求验证产品价值，同时核算交付、平台运行及模型成本，逐步形成持续经营的数据与AI业务。

**预期产出：标准接入与开放服务、分析及AI产品、行业报告与规范、可商业化的服务组合。**

## 本轮对齐重点

围绕现有五类数据问题，优先对齐统一标准、公共模型、质量治理和服务复用的建设范围，再明确AI及内外部产品如何共用这些基础能力。

未来1—3年的持续演进以能力成熟度为依据：核心数据可信，公共能力可复用，应用与服务可扩展，产品价值可验证。治理贯穿全过程，对内赋能、对外商业化和行业输出持续跟随可用能力推进。

其中，指标平台坚持：**企业提供统一标准，景区保留专属定义能力；数据、指标与AI使用都遵守景区隔离边界。**
