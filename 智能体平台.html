2.3 平台建设

思路：数字大脑本身就是智能体管理台。底层依托 Coze、火山方舟、Quick BI 和合作企业的成熟能力，上层以数字大脑统一管理所有智能体，覆盖能力定义、调试、发布、运行、管控、审计的全流程。

2.3.1 总体架构

中间三层均为数字大脑的模块；最底层为依托的成熟能力。

模块 管什么
工具中心 所有能力统一定义：Tool（接业务接口、查数据、跑脚本）、Skill（提示词 + 工具 + 编排）、MCP（接外部工具）、Agent（人格 + 多个 Skill）；统一版本、共享、锁定
知识中心 数据库知识（登记数据源和表，第一章的数仓直接可用）、网络知识（联网检索、白名单站点）、向量知识（景区文档、图文）
运营与审计 工作台看任务、成功率、成本；对话里调试执行过程；高风险动作人工审批；发布前跑评测回归
系统中心 集团 / 景区两级组织、角色权限、可见范围；模型接入与预算护栏；按调用链追踪日志

2.3.2 全流程管理

现有能力的纳入方式：

现有能力 纳入数字大脑
扣子上的 5 个智能体 通过接口注册为 Tool，再组装成 Agent，统一入口、计量和审计
智能问数、智能数据解读 注册为 Tool，由 Agent 调用
合作企业的手语能力 以 MCP 或 HTTP Tool 接入
售票、订单、核销等业务接口 注册为 HTTP Tool，所有 Agent 共用
第一章的数仓与认证指标 登记为数据库知识，供数据库查询类 Tool 使用

2.4.3 质量与成本

管什么 怎么管
上线质量 评测中心为每个 Agent 维护回归用例，发布新版本前必须跑通
线上效果 工作台看任务成功率；答错的问题补进知识中心和回归用例
调用成本 工作台按景区、按 Agent 看 Token 成本；系统中心设预算上限和告警
版本升级 版本可对比、可回滚；升级一次，所有景区同步受益

2.4.4 安全底线

底线 做法
只用授权数据 任务、日志、成本按景区强隔离；景区只能看到本景区数据和公开能力
高风险动作要审批 高安全等级的工具调用强制人工审批，Skill 层不能绕过
查数只读 数据库查询类 Tool 只允许 SELECT
不碰敏感信息 手机号、证件号不进入对话和知识库，展示时脱敏
可追溯 每次调用按调用链留痕，出错步骤可定位
